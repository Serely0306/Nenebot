# 国服抓包与常用静态查询精简版

代码最初在独立的 `lunabot-new` 副本中修改与验证，副本的数据是独立复制，未使用指向原项目的软链接。提交时将变更映射回现有仓库的 `lunabot/` 路径，通过独立分支进行服务器测试，不把副本目录、测试文件、生产配置或数据纳入提交。非 Sekai 插件保持原样。

精简目标是停用无法连接的实时游戏 API，以及减少不常用功能继续积累图片。共用现有资源的常用混合查询保留完整分支，不要求所有查询都必须读取个人 Suite。

## 功能范围

| 类别 | 行为 |
| --- | --- |
| 区服 | 用户命令、组卡数据更新、MSR 推送仅处理国服；历史默认日服自动回退到国服，不改写旧记录 |
| 账号与抓包 | 保留绑定、主账号、多账号、抓包模式、数据状态、隐私设置、黑名单、已有验证记录 |
| Suite | 保留持有卡牌、卡盒、育成、挑战 Live、角色等级/牵绊、资源统计、个人成绩/进度/B30、个人活动记录和抽卡记录、组卡 |
| MySekai | 保留资源图、蓝图、家具、角色对话、大门、唱片、材料、MSR 普通刷新和生日刷新订阅推送 |
| 实时功能 | 停用独立个人信息、榜线/预测/查房/追踪、心愿榜、游客注册、送火、新账号验证 |
| 公开查询 | 停用独立查活动、查歌曲/曲绘/谱面、卡面原图下载、卡池查询、公开养成总览、虚拟 Live、表情和娱乐功能及相关通知订阅 |
| 混合命令 | 保留 `/card` 的普通多卡列表、`box` 筛选和单卡详情；`/卡牌一览` 的全部原有筛选、排序、技能与持有卡叠加；歌曲列表、定数表的公开列表及个人成绩筛选；区域道具的个人分支与 `all/full` 总览；普通和 `max/submax` 顶配组卡模拟 |
| 纯计算 | 保留 `/实效` 的五人数值计算，不读取游戏 API 或图片 |

公开 MasterData、曲目匹配、事件信息、称号和图片处理等内部函数仍供保留功能使用。静态卡牌列表和单卡详情、歌曲列表、区域道具总览、顶配组卡不要求先上传 Suite；个人持有卡、成绩、育成和普通组卡仍需要 Suite。退休模块不再导入，旧命令由轻量处理器接管；混合模块中独立停用的命令在数据读取前拒绝。单卡详情的底部提示也改为有效的卡牌一览命令。

停用命令回复“当前不支持功能，请更换前缀使用HarukiBot NEO功能”，根据本次原始消息生成替代写法，并保留参数：

- `*查曲 xxx` -> `/查曲 xxx`
- `/查曲 xxx` -> `查曲 xxx`

OneBotFilter 会改写事件内的前缀，因此通过 `get_msg` 读取原始消息。获取超时或平台不支持时给出两种前缀规则，不猜测用户使用的前缀。

## 数据与权限

基础资料改由上传 Suite 生成，姓名、主卡组和成绩统计不再访问游戏 profile API。只有 MySekai、没有 Suite 时使用“未上传Suite资料”的中性身份与默认头像。全部图中数据仍是抓包快照，不代表实时游戏状态。

保留对 `Nenebot_tools` 的 HTTP 请求，用于读取已上传的 Suite/MySekai、上传时间、生日事件和维护订阅。`gameapi.py` 仅允许这五类配置端点生效；历史配置里的 profile、ranking、photo 等实时端点会被忽略。

绑定只进行国服 ID 格式检查，保留原有绑定上限、频率限制、黑名单与隐私逻辑，不再通过在线 API 验证账号是否存在。上传文件不能证明账号所有权，新账号验证停用；已有验证记录继续有效，需要验证的操作仍受限。

MSR 用户订阅仍读取历史“国服”存储键；群权限保留原代码曾误用的“日服”存储键，避免迁移后丢失既有订阅或意外开放群权限。其他旧订阅数据留存，但不再调度或出现在有效订阅列表中。

### 照片限制

现有 MySekai 主响应通常只包含照片索引和拍摄时间。实际图片原本由 Haruki API 带游戏会话请求独立的 photo 接口获得，`Nenebot_tools` 没有对应离线图片接口。

`/msp` 保留命令和已有内嵌 `thumbnail` 的读取能力；只有索引时明确提示无图片，不调用实时 API。若要恢复完整照片功能，需要另行扩展 catcher/iOS 的照片响应捕获和服务端图片存储；本轮未改变抓包协议。

## 资源回退

现有生产配置已在 `cn.rip.sources` 中依次配置国服源和日服备用源，可以直接沿用。各源按顺序尝试；新增图片解码校验，某源即使返回 HTTP 200，但内容是 HTML/坏图，也会继续尝试下一源，避免缓存错误响应。

`cn.masterdata.sources` 只能配置国服镜像。MasterData 管理器按版本选择镜像，把日服加入其中会把更高版本的日服数据用于国服计算，不能用作图片式回退。保留 `jp` 内部资源配置，用于共用角色图标等原有资源依赖，不开放日服用户功能。示例中的 `xxx` 仍需换成实际地址；不要用示例覆盖生产配置。

卡牌限定类型判断改为使用传入的国服 MasterData，不再强制读取日服。当前本地国服快照包含 1243 张卡和 7 类供给类型，没有缺失映射，与原日服判断结果差异为零；遇到未知卡或缺失分类仍回退为原有的普通类型。

## 性能与配置

| 配置文件 | 字段 | 新默认/建议值 |
| --- | --- | --- |
| `config/sekai/asset.yaml` | `image_cache_max_bytes` | `67108864`，静态与解包图片共享 64 MiB 像素缓存预算；`0` 禁用 |
| `config/sekai/sekai.yaml` | `mysekai.render_concurrency` | `1`，命令与两种推送共享绘图并发限制，启动时读取 |
| 同上 | `mysekai.site_render_concurrency` | `1`，站点地图分批创建与回收任务 |
| 同上 | `mysekai.msr_push_concurrency` | `1`，普通与生日推送批次并发 |
| `config/global.yaml` | `painter.process_num` | 示例改为 `1`，生产当前为 `2`，后续部署时单独评估并合并 |
| `config/sekai/gameapi.yaml` | `cn` 下五个上传端点 | 沿用生产 `Nenebot_tools` 的 5000 端口及鉴权配置 |

图片缓存返回副本，LRU 淘汰仅关闭缓存自己持有的图像。静态文件修改会使缓存失效。64 MiB 只限制这份共享像素缓存，不是进程总内存上限；MasterData、画布、其他插件和正在使用的图片另占内存。

### 磁盘占用与取舍

2026-10-28 对本地副本 `data/sekai/assets` 的只读统计约为 1130 MiB：MasterData 918 MiB、解包资源 164 MiB、静态资源 38 MiB、派生卡牌缩略图 8 MiB。其中解包图片约 154 MiB、音频约 9 MiB。该数字不是服务器当前占用，也不是本轮新增或节省的空间。

图片按需下载，不存在为了公开列表预先下载全部图片的任务。卡牌列表、歌曲列表、区域道具和组卡主要共用 Suite/MySekai/B30 已使用的缩略图与 MasterData，因此保留这些完整查询更符合实际用途。单卡详情仍可能按需缓存卡图、服装缩略图和活动横幅；这部分按常用功能保留。

64 MiB LRU 仅控制内存，不能限制磁盘。现有 `rip`、派生卡牌缩略图和绘图结果缓存仍没有统一的磁盘总量或闲置淘汰策略；资源过期参数用于重新下载，不会主动清掉不用的文件。停用功能只能减少后续下载，不会自动回收历史资源。本轮没有删除任何图片、数据或 MasterData，也没有把按需缓存关闭以造成重复下载；磁盘清理和设置磁盘预算应另行处理。

如果实际配置已写有更高并发值，旧值会继续生效，需在后续部署时显式合并上表配置。本轮只修改示例，没有修改真实运行配置。别名同步、新曲、APPEND、广告统计、公开养成总览等后台任务或更新钩子已停止注册；组卡更新和 MSR 推送保留并限国服。Pandas 改为 B30 首次读取定数表时再导入，停用模块的 OpenCV/榜线预测等不再因导入而加载。

## 验证与部署边界

本地使用 `D:\conda\envs\sekai\python.exe` 做隔离测试，覆盖快照字段转换、前缀提示、真实处理器路由、别名兼容、旧 MSR 存储键、图片回退/LRU、绘图限流与异常取消、离线照片和端点白名单；另执行真实混合处理器的 AST，验证卡牌多卡/单卡/持有筛选、卡牌一览原有参数、歌曲公开/个人筛选、区域道具总览/个人分支、实效计算与组卡 profile 选择，并检查所有源码语法及 YAML 示例。

结果：82 项隔离测试通过，129 个 Python 源文件通过语法检查，4 份修改后的配置示例通过 YAML 解析。真实帮助解析器解析出 30 段帮助、152 个有效别名，覆盖 50 个保留固定命令入口及 4 个 MSR 订阅入口。状态查询验证了目标账号、标题与数据来源一致，并遵守目标用户的 ID 隐藏设置；综合统计和成绩使用同一份 Suite 快照。

本机副本缺少完整生产配置，`sekai` 环境缺少 NoneBot、aiohttp 及组卡扩展等完整运行依赖，因此没有启动整个机器人，也没有进行真实消息发送或整图性能压测。测试文件在本地忽略列表内，不纳入 Git 跟踪。

部署前备份服务器 `config/` 与全部 `.env*`，核对目标分支不修改运行配置及数据；在原目录切换分支，保持生产数据路径、鉴权、账号记录、订阅数据库和资源源地址。先停旧实例再启动新实例，避免两个进程同时读写同一订阅数据库或重复推送。源码内的新参数已有保守缺省值；如需更改实际配置，仅合并明确字段并保留差异记录，不使用示例覆盖配置。回退时切回部署前的分支与提交，按需恢复已备份配置。
